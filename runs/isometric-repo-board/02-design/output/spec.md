## 1. Requirements & Functional Behavior

**R1 — Switchable view, list stays default, origin-aware return.** Header gains a List | Board toggle. Routes: `#/` list (default, unchanged), `#/board` board, `#/repo/<encodeURIComponent(path)>` detail (unchanged, existing `?tab=` behavior preserved). The hash router splits today's two-way branch into three: `#/repo/…`, `#/board`, default list. Hash back/forward and `#/`↔`#/board` toggles preserve per-view scroll **in-session only** (no reload persistence — matching current list behavior; F5 persistence explicitly rejected, human decision D2 2026-09-30). `closeDetail()` navigates to the stored origin (`#/board` when detail was opened from a board tile, else `#/`; human decision D3). `showDetail` captures `boardScrollY` vs `listScrollY` based on origin (never overwriting the other view's position). Board tiles carry DOM id `board-tile-<encodeURIComponent(path)>` and class `tile` inside `<main id="board-view">` (mirroring `<main id="list-view">` / `<main id="detail-view">`). On return to `#/board`, focus restores to `board-tile-<encodeURIComponent(lastOpenedPath)>` (falling back to `#board-refresh`); on return to `#/`, the existing `repo-link-<encoded>` lookup is kept. Grounding (symbols normative; line numbers as of working tree 2026-09-30): `closeDetail` (dashboard.html:1183), `route()` two-way branch (dashboard.html:1187–1202), `listScrollY` (dashboard.html:1178), focus lookup (dashboard.html:1200). The command palette (`renderPalette`/`paletteOpen`, dashboard.html:1681–1712) keeps its repo-jump behavior unchanged and gains one view command: a query matching `/board/i` offers `Board view → #/board` as the first item; selecting it navigates to `#/board`.

**R2 — One tile per tracked repo.** Tiles derive from `GET /api/repos` in response order. Board renders exactly N tiles for N tracked repos — no silent omissions, no auto-discovered extras. Board order is always API order: list sort (`name`/`recent`), grouping (collection/folder/project/none), filters, search, and collections never affect the board; the spatial layout is its own organization and the board offers no filtering (exact-N-tiles is the point). Tile labels disambiguate multiple checkouts of one project via `status.project_path` / `status.is_worktree` when present in the payload (guarded `?.`, falling back to the short path) — one tile per tracked path either way.

**R3 — Status-to-stage mapping (frozen pseudocode).** Each tile carries `data-stage` computed by a pure `repoStage(res, status)` function, defensive against sparse fixtures (the harness mock omits `stale_branches`). Precedence is table order; HTTP status is checked before body, `410` before other failures:

```
gone             = res.status === 410
error            = res.status !== 410 && !res.ok  // 400, 404, 503, network; verbatim-safe
loading          = fetch outstanding
// A rejected/timed-out fetch (no response object) maps to `error`.
attention-dirty  = status.dirty?.is_clean === false
attention-sync   = ((status.sync?.ahead ?? 0) + (status.sync?.behind ?? 0)) > 0
                   && status.sync?.has_upstream === true
attention-stale  = (status.stale_branches ?? []).length > 0
healthy          = otherwise
```

A `healthy` tile whose `status.sync?.has_upstream === false` additionally shows a muted badge element with `data-badge="no-upstream"` (human decision D1: no-upstream is healthy-family). Needs-attention oracle (intent §2): `data-stage` starts with `attention-`, or `gone`, or `error` — `healthy` (badged or not) and `loading` never count. Health is never color-alone: every `attention-*`/`gone`/`error` stage pairs color with a distinct marker shape plus a text status line on the tile.

**R4 — Tile content and access.** Tile shows repo short name, `branch · last_commit.relative` label, and status summary. A tile whose path is in the local organization store's `pins` array (key `repo-root-tracker.organization.v1`, guarded: store absent or unreadable means no marker, never a crash) shows the same ★ marker as the list and exposes pinned state in the tile's accessible text (aria-label or status line, e.g. '· pinned'). Board chrome and tile text use the dashboard CSS custom properties (`--surface`, `--text`, `--muted`, `--accent`, …); stage hues are declared once as board-section CSS variables so themes can override them — consistent with the GitHub Dark theme overhaul, and still D4 topology-only since no test asserts color. Tile markup is a link to `#/repo/<encodeURIComponent(path)>` — citing the exact functions (human decision: encoding citation required): href built with `encodeURIComponent(r.path)` (dashboard.html:1014); `route()` parses with `decodeURIComponent(encoded)` and restores focus via `encodeURIComponent(lastOpenedPath)` (dashboard.html:1187–1200); server side decodes with `unquote(params.get("path", ""))` (`server.py:Handler.do_GET`). Inner SVG has `role="img"` and `aria-label="<name>: <summary>"`; `<summary>` vocabulary is free-form, but the per-tile text status line is a frozen, asserted element: tests assert `data-stage`, link href, badge presence, branch·relative text, and status-line presence. Keyboard focus lands on the tile link with a visible `:focus-visible` outline; Enter navigates to detail. The SVG island honors `prefers-reduced-motion`. Screen-reader and keyboard equivalence with the card list (human decision 2026-09-30).

**R5 — Snapshot refresh without double-fire.** Statuses fetch once per board visit (same per-repo `GET /api/repos/status?path=` pattern the cards use, async with loading stages). A Refresh control (`#board-refresh`) re-fetches all non-`gone` tiles; `gone` tiles require a full board revisit, defined as navigating to `#/` (or any other hash) and back to `#/board` — re-setting the same hash fires no route event; no per-tile retry buttons. While any tile fetch is outstanding, Refresh is either disabled or in-flight fetches are aborted via `AbortController` — implementation picks one, Stage-03 review confirms; double fan-out never occurs. A per-tile fetch timeout (or manual-refresh override that abandons hung tiles to `error`) is required so a wedged git subprocess cannot disable Refresh indefinitely.

**R6 — Empty state.** Zero tracked repos renders an explicit empty state pointing at the existing add-repo flow — never a blank island.

**R7 — Grid and overflow (per-page layout).** With `M = min(tiles_on_page, 25)`: columns = `min(5, ceil(sqrt(M)))`, rows = `ceil(M / cols)`; the island slab viewBox is computed from rows/cols and the §2 tile relations. N > 25 pages into islands of 25 with pager `#board-prev` / `#board-next` plus a `role="status"` node carrying `tabindex="-1"` and text `Page x of y`. Page resets to 1 on Refresh; page persists across detail-back in-session; focus moves to the pager status node on page change (programmatic focus, not `:focus-visible`).

**R8 — Load budget (measurable predicate).** Two predicates, one rule each: correctness is `wait_for_function` on the count of `#board-view .tile[data-stage]` equaling N; the budget gate is `page.wait_for_selector('#board-view .tile[data-stage]', timeout=1000)` from navigation start (not from `/api/repos` resolution), on localhost Chromium at 1280×900 and 390×844, with zero page errors (human decision D5 2026-09-30: hard gate at 1000 ms plus mobile viewport). `#board-view` and the `tile` class are frozen interfaces (see §2). Per-tile status resolution is git-bound and carries no budget; it must show `loading`, never block the grid. Unbounded per-tile fan-out is accepted as consistent with the list view (`ThreadingHTTPServer` already serves it); no new backend concurrency work.

**R9 — No backend, no mutations, clean-room.** No new API routes; no changes to existing routes, the `#/repo/<encoded-path>` contract, `/api/*` shapes, or the default view. The board view itself initiates only `GET /api/repos` and `GET /api/repos/status?path=` — no POST/DELETE, no git-mutation affordances anywhere in the view. Tile-click detail navigation reuses the existing `showDetail` fetches (`/api/repo`, `/api/github`, diffs) unchanged; those are not board-initiated. Clean-room, no exceptions (intent §4, enforced here not merely referenced): no import of or reference to any groveboard path; no copied markup, path data, or numeric constants — parametric 2:1 projection per §2 only. Stage-03 review must diff board SVG code against `renderTileSvg` / `renderGroveIslandSvg` in groveboard `app.js @5ab3380` and record a clean result. All product code lands in `src/repo_root_tracker/dashboard.html`.

## 2. Architecture & Data Contracts

- **Code location:** frontend only — `dashboard.html` gains a `board-view` section, `renderBoard()`, and the pure `repoStage()` mapper implementing the R3 pseudocode verbatim; router `route()` gains the `#/board` branch plus `boardScrollY` and origin tracking per R1.
- **Data in:** `GET /api/repos` → `[{path}]`; per tile `GET /api/repos/status?path=<encodeURIComponent(path)>` → `RepoStatus` dict; codes reused per R3: 400/404/503/network → `error`, 410 → `gone`.
- **Data out:** none. No POST/DELETE, no new endpoints, no schema changes.
- **Tile geometry (topology-only, human decision D4):** standard 2:1 isometric projection expressed parametrically: top-face diamond with diagonals `(TW, TH = TW/2)`; screen position of tile `(c, r)` at `x = (c − r) · (TW + gx)/2`, `y = (c + r) · (TH + gy)/2` (gx/gy = fixed gutters); island slab = bounding diamond of the grid extruded downward by depth `D` with two shaded faces. Pixel constants, colors, marker shapes, and slab padding are implementation detail and **may diverge** — the asserted contract is `data-stage` + tile-link href + labels only. Studied for proportions, never copied: `renderTileSvg` / `renderGroveIslandSvg` in `app.js` of groveboard at commit `5ab3380` (that repo ships no LICENSE file; the no-exceptions clause stands regardless).
- **Frozen interfaces for Stage 03:** route `#/board`; view container `#board-view` (a `<main>` sibling of `#list-view` / `#detail-view`); tile class `tile`; palette `/board/i` → `#/board` first-item command; `data-stage` value set `{loading, healthy, attention-dirty, attention-sync, attention-stale, error, gone}` with R3 pseudocode as the normative mapping; per-tile text status line (asserted in tests, not free-form); `data-badge="no-upstream"` muted badge; tile id `board-tile-<encodeURIComponent(path)>`; tile-link href `#/repo/<encodeURIComponent(path)>`; `#board-refresh`; pager `#board-prev` / `#board-next` + `tabindex="-1"` `role="status"` page text.

## 3. Skill & Dependency Capabilities

- Offline skills routed via `tink-route`: none — no capability gap; vanilla JS/SVG plus the existing backend suffice.
- External libraries or skills scouted via `skill-scout`: none — no 3D/canvas libraries; hand-built inline SVG keeps the single-file dashboard convention and zero new dependencies.
